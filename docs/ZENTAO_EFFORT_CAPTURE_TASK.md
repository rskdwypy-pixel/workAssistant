# 抓包任务：禅道 18.3「工时」相关接口（给浏览器抓包 AI 的指令）

> 目的：为「工作日历」的工时编辑 / 删除 / 补填，以及「我的工时汇总」接口，拿到**真实**请求与响应。
> 方法沿用上一轮需求抓包：Playwright 驱动本机已装的 Google Chrome（`channel: 'chrome'`），用开源版入口 `/zentao/`（企业版 `/biz/` 授权已过期，别用）。
> 登录账号由使用者提供。**不要把账号密码、cookie 写进交付物**（见「脱敏」）。

---

## 0. 准备与约束

- 先自己新建一个**测试任务**（标题带「【插件联调·可删】」），指派给自己，预计 8 小时，状态保持「未开始」。所有写操作只对这个任务做。
- **不要动别人的任务、别人的工时。**
- 全部做完后：删除自己造的工时记录，再删除测试任务（或取消 / 关闭），并在报告里写明最终状态。
- 交付物放到仓库 `docs/zentao-capture-<日期>-effort/`；脚本和原始响应都留。
- **脱敏**：cURL 里的 `cookie` 头一律替换成 `<COOKIE>`；响应里若出现密码、token 也替换。

每个请求都要给出：**完整 URL、方法、请求头里与业务相关的（content-type / x-requested-with / referer）、请求体（multipart 或 urlencoded 的全部字段，原样）、响应状态码、响应体原文**（HTML 也给，JSON 也给）。

## 任务 A：「我的工时汇总」有没有一次读出区间内全部工时的接口？

目标：判断能否一次请求拿到"我在某段日期里每天填了什么"，这样日历就不用逐任务读工时。

1. 在禅道界面找「**日志**」相关入口：地盘（我的地盘）里的「日志 / 工时 / 日历」，以及顶部导航里的同类入口。逐个点开，记录**页面 URL 和页面里发出的数据请求**。
2. 重点找：
   - 日历视图（按月看每天的日志），例如 `effort-calendar-...`、`my-effort-...`、`effort-personal...` 一类路由（名字以实际为准，不要硬套）；
   - 列表视图（按日期区间列出我的日志），是否支持 **起止日期 / 月份 / 用户** 参数。
3. 对每一个找到的页面，用 `.json` 后缀（或 `X-Requested-With: XMLHttpRequest` + `Accept: application/json`）取一份 JSON，给出：
   - 请求 URL（含参数含义说明）；
   - 响应里每条日志的**全部字段**（至少要有：日志 id、日期、账号、消耗、剩余、工作内容、关联对象类型和 id、所属执行 / 项目）；
   - 是否分页、每页多少、怎么翻页；
   - **能否查指定月份 / 指定日期区间**，能否查**别人**的日志（权限）。
4. 结论写清楚：**有 / 没有**可用的区间汇总接口；有的话哪条最合适。

## 任务 B：补填过去日期的工时

在测试任务上用「记录工时（task-recordEstimate）」：

1. 先抓一次**正常记今天**的完整请求（作为对照）。
2. 再分别用 `dates[1]` 为以下日期各记一条（消耗各 0.5 小时，工作内容写明是哪一天）：
   - 昨天
   - 7 天前
   - 35 天前（跨月）
   - **明天**（未来）
3. 对每一条记录：是否成功？响应是什么？失败的话**错误提示原文**。
4. 记完后读一次 `task-recordEstimate-<任务ID>.json`，给出 `efforts` 列表的**全部字段**（特别是每条工时的 **id** 字段名）。
5. 额外验证并回答：
   - 任务「未开始」时记工时，任务状态会不会自动变成「进行中」？
   - `left`（剩余）不填 / 填 0 / 大于预计，分别会怎样？
   - 一次提交多行（dates[1]..dates[5] 填多行）是否都生效？
