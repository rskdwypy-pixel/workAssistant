# 「工作日历」PRD：报告页 + 工时填报合并改版

> 状态：方案已确认（2026-10-23：名称「工作日历」、标准工时 8h 可在设置里改、周末不计缺填、草稿允许保留）。**P0、P2 已实现**，P1 待抓包（指令见 `ZENTAO_EFFORT_CAPTURE_TASK.md`）。
>
> P2 实际做了：统计面板（我的：按执行、任务 Top5；全员：成员 × 日期热力图）、我的/全员切换（全员格子、只读抽屉）、待办页「工时待补」提醒、日报/周报/月报采集与工时日历共用任务工时缓存。其中统计面板「按项目」落地为「按执行」（我的任务列表里只有执行名，没有项目名）。
>
> P0 与方案的两处差异：① 点日期打开「工时」抽屉，日报通过抽屉里的「📄 查看日报」按钮打开（没有把日报嵌成同一抽屉的第二个页签，避免重写 470 行的日报窗口）；② P0 的「我的工时」只覆盖「我相关的任务」（指派给我 / 我创建 / 我完成 / 我关闭 / 我取消），原因见 effortService 注释，等 P1 确认有「我的日志」汇总接口后补齐。
> 前端存储：今日工时累加值与用户列表缓存已删除；`workAssistantConfig`（后端地址 + 设置页配置副本）标记为【待迁移】，守护测试 `test-no-local-data.cjs` 里单独列出。
> 背景：报告页本身就是日历；工时填报（记工时）与日报 / 周报 / 月报是同一批数据的"写入"和"读出"，合并成一个页面，不再单独加标签页。

---

## 1. 目标与原则

**一句话**：一个日历页，回答三个问题——「我这天填了多少工时？」「我这个月有没有漏填？」「团队这周的工作量怎么样？」，并且能在同一页直接补填。

**三条原则**

1. **禅道是唯一数据源**。工时、任务、日报全部以禅道为准；前端不存任何业务数据（见 §6）。
2. **读写同页**。看到某天缺了工时，点进去就能填，填完日历立刻更新。
3. **填报驱动报告**。工时记录里的"工作内容"就是日报的原料，填得越规范日报越准；不做第二套录入。

---

## 2. 标签页名称

| 候选 | 评价 |
|---|---|
| **工作日历（推荐）** | 页面主体就是日历，每一天都有"工时 + 日报"；以后加周 / 月 / 全员视图都装得下 |
| 统计 | 概括但偏被动，看不出能填报 |
| 工时 | 太窄，装不下日报 / 周报 / 月报 |
| 工时与报告 | 准确但太长，标签放不下 |

**推荐「📅 工作日历」**；若更想要通用名，退而求其次「📊 统计」。菜单顺序：待办、任务、Bug、需求、文档、**工作日历**（原「报告」位置，仍在最后）。

## 3. 页面设计

### 3.1 整体结构

```
┌ 📅 工作日历   本月 87/160h · 缺填 2 天 · 逾期任务 3         [我的 | 全员]  ┐
│                                                                          │
│  ‹  2026 年 10 月  ›  [本月]                          [月报] [周视图]     │
│ ┌────┬────┬────┬────┬────┬────┬────┬──────┐                             │
│ │ 一 │ 二 │ 三 │ 四 │ 五 │ 六 │ 日 │ 本周 │                             │
│ ├────┼────┼────┼────┼────┼────┼────┼──────┤                             │
│ │ 20 │ 21 │ 22 │ 23 │ 24 │ 25 │ 26 │ 32h  │                             │
│ │8.0h│7.5h│ ⚠  │4.0h│    │    │    │[周报]│                             │
│ │ ● │ ● │0.0h│ ◐  │    │    │    │      │                             │
│ └────┴────┴────┴────┴────┴────┴────┴──────┘                             │
└──────────────────────────────────────────────────────────────────────────┘
点某天 → 右侧抽屉：[工时] [日报] 两个页签
```

### 3.2 日历格子

每个格子显示：日期、**当天工时**（小时数）、工时进度条（相对每天标准工时）、日报状态点。

| 状态 | 表现 |
|---|---|
| 已填满（≥ 标准工时） | 绿色 |
| 已填但不足 | 琥珀色，显示 `4.0h` |
| 过去的工作日、一小时都没填 | 红色 ⚠ |
| 周末 / 未来 | 灰色，不提醒；周末有填则照常显示 |
| 今天 | 高亮边框 |
| 日报 | 右下小圆点：已生成 ● / 未生成 ○ |

右侧多一列「本周」：本周累计小时 + 周报入口；头部有「月报」入口（保留现有行为）。

### 3.3 页头统计条

本月累计 / 应填（工作日 × 标准工时）、**缺填天数**（可点：跳到第一个缺填日并打开抽屉）、逾期任务数（可点：打开抽屉的任务列表）。

### 3.4 日抽屉（点某一天）

**页签一「工时」**

- 当天工时明细：每条 = 任务名 + 小时 + 工作内容，可**编辑 / 删除**。
- **＋ 填报**表单（日期固定为所点的这一天，所以"补填过去"= 点过去的格子）：
  - 任务：下拉，默认列出我进行中 / 未开始的任务，支持搜索；
  - 消耗小时、剩余小时、工作内容（必填，因为它是日报原料）。
- 当天还差多少小时：`已填 4.0h，还差 4.0h`，提交后实时变化。

**页签二「日报」**：现有的日报查看 / 生成 / 重新生成 / 推送，原样搬进来。

### 3.5 「全员」视角

沿用现有的"我的 / 全员"切换。全员模式下日历格子显示**团队当天总工时**，抽屉里是「成员 × 工时」表；页头统计条改为团队累计、缺填人数。全员视角只读，不提供代填。

### 3.6 统计面板（日历下方，可折叠）

- 本月**按项目**工时占比；
- 本月**工时最多的任务** Top 5；
- 全员模式：成员 × 日期热力图（复用现有 `computeReport` 的 `byDay`）。

## 4. 数据与接口

### 4.1 数据来源（全部来自禅道）

| 数据 | 来源 | 现状 |
|---|---|---|
| 某任务的工时记录 | `task-recordEstimate-{id}.json` → `efforts` | 已实现 `getTaskEfforts` |
| 周期内有变动的任务 | 执行下任务列表 + `lastEditedDate` 过滤 | 已实现于 `reportCenter.collectRaw` |
| 新增工时 | `task-recordEstimate`（POST） | 已实现 `recordTaskEstimate`，**日期写死今天，需参数化** |
| 修改 / 删除工时 | `task-editEstimate-{id}` / `task-deleteEstimate-{id}-yes` | **未验证，需抓包** |
| 我的日志汇总（若有） | 禅道「地盘 → 日志」类接口，一次读出区间内全部工时 | **需抓包确认是否存在** |

### 4.2 性能：用缓存做"真增量"

`collectRaw` 现在每次要扫全部执行、再逐任务读工时，慢。新做法：

- 新增 `effortService`：按**任务**缓存工时记录，缓存键 = 任务 id + `lastEditedDate`（记工时会刷新任务的最后编辑时间，所以没变就不用重读）。
- 刷新时只整拉"任务列表"（便宜），再**只重读 lastEditedDate 变了的任务**的工时——这才是真正的增量。
- 沿用 `zentaoCache` 的机制：先画缓存、再刷新、写操作后失效、换账号自动作废。
- 若抓包确认有"我的日志"汇总接口，「我的」视角直接用它（一次请求），全员视角仍用上面的方式。

### 4.3 新增 / 调整的接口（草案）

| 接口 | 说明 |
|---|---|
| `GET /api/efforts?month=YYYY-MM[&scope=team]` | 区间内每天工时 + 明细（带 `cache=only`、`syncedAt`、`diff`） |
| `GET /api/efforts/day/:date` | 某天明细（任务、小时、工作内容、effortId） |
| `POST /api/efforts` | 新增：`{taskId, date, consumed, left, work}`（补填 = 传过去的日期） |
| `PUT /api/efforts/:id` / `DELETE /api/efforts/:id` | 编辑 / 删除（第二阶段，需抓包） |
| `GET /api/efforts/tasks` | 填报下拉用：我进行中 / 未开始的任务 |
| `GET /api/reports/calendar` | 现有；每个 day 增加 `hours`、`standard`、`status` 字段 |

标准工时放服务端配置（默认 8 小时 / 天），设置页可改；不再写死在前端。

## 5. 与其他模块的联动

- **待办页**：缺填提醒——页头 / 角标提示"昨天只填了 3.5/8h"，点击跳到工作日历对应日期并打开抽屉。
- **任务拖进度弹窗**：保持不变，填完调用同一个后端，并让工时缓存失效。
- **日报生成**：改读同一份工时缓存，生成更快；工作内容成为日报原料。
- **任务 / Bug 卡片**：今日工时不再读 localStorage，改读后端。

## 6. 前端存储治理（"所有数据都不依赖前端存储"）

**原则**：前端只允许保存**界面偏好**和**未提交的草稿**；任何业务数据（工时、任务、用户、配置内容）只在后端 / 禅道。

现状盘点（`extension/` 下 `localStorage` 全部用途）：

| 键 | 用途 | 处理 |
|---|---|---|
| `workTime_*`、`taskWorkTime_*` | 今日已填工时（浏览器本地累加） | **删除**，改读后端（本期） |
| `zentao_users` | 禅道用户列表缓存 | **删除**，后端已有 `data/zentao-users.json` 和接口 |
| `workAssistantConfig` | 含后端地址（引导必需）+ 配置副本 | **后端地址保留**（前端要先知道后端在哪才能请求它，属引导信息）；配置内容副本逐处核对后去掉，一律读后端 |
| `lastTabMode`、`debugMode`、账号提示的跳过标记 | 界面偏好 | 保留 |
| `taskDraft`、`bug_draft` | 表单草稿（未提交内容，刷新不丢） | 保留，**待你确认**（见 §9 问题 4） |

验收：全局搜索 `localStorage` 后，剩余键只有上表"保留"类；新增一个测试扫描 `extension/*.js`，出现不在白名单里的键就失败，防止以后回潮。

---

## 7. 不做什么

- 不做代填（给别人填工时）、不做工时审批。
- 不做法定节假日 / 调休识别（周末按周六日算；禅道没有这个数据）。
- 全员视角只读。
- 不改任务看板的拖进度交互。
