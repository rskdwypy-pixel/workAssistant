# 「需求拆任务」与「Bug 转任务」PRD

> 状态：P0（Bug 转任务）、P1（需求拆任务）已实现并实测（2026-10-23）；P2（AI 拆分建议、任务卡片来源标签）未做。实测结论：必须 multipart + X-Requested-With；Bug 只在 URL 里关联；禅道不拦重复转（插件拦）；响应不带任务 ID（按标题回查）。详见 `src/services/taskLink.js` 头部注释。抓包指令见 `ZENTAO_STORY_BUG_TASK_CAPTURE_TASK.md`，回复后按 §9 分阶段开发。
> 背景：需求、Bug、任务三块已经各自成页（需求页可新建 / 编辑 / 删除，Bug 看板可确认 / 解决 / 激活，任务看板可记工时）。但它们之间还是断的：看到一个需求，要去禅道里手工建任务；看到一个 Bug，要自己抄标题再建任务。这一期把三者连起来。

---

## 1. 目标

1. **需求拆任务**：在需求详情里，把一个需求拆成若干开发任务，一次建好，任务与需求在禅道里自动关联。
2. **Bug 转任务**：在 Bug 详情 / 卡片上，一键把 Bug 转成一个任务，带上 Bug 的信息，任务与 Bug 在禅道里自动关联。
3. 建出来的任务**马上出现在任务看板**，不用手工刷新同步。
4. 能看出"这个需求已经拆了哪些任务""这个 Bug 已经转成了哪个任务"，避免重复拆、重复转。

**非目标**：不改需求 / Bug 本身的评审、解决流程；不做任务的批量编辑；不做跨产品的需求合并拆分。

---

## 2. 需求拆任务

### 2.1 入口
需求详情弹窗头部新增「拆任务」按钮（在「编辑」旁）。

- 需求状态不允许拆时（草稿 / 评审中 / 已关闭，具体以抓包为准）按钮置灰，悬停说明原因。
- 需求下**已有任务**时，弹窗顶部列出它们（任务名、负责人、状态、工时），提示"已经有 N 个任务，继续拆会新增"。

### 2.2 弹窗

```
┌ 拆任务 · #172 iOS 通用自动化方案 ─────────────────────────────┐
│ 已有任务（2）：接口设计 · 何俞龙 · 进行中 | 页面开发 · 李佳成 · 未开始 │
│                                                               │
│ 创建到执行：[ 2026 年工作日志记录 ▾ ]   ⓘ 该需求已关联此执行     │
│                                                               │
│ [✨ AI 拆分建议]                              合计 14h · 4 个任务 │
│ ┌──┬────────────┬────┬──────┬─────┬──────┬────────┐          │
│ │ #│ 任务标题     │ 类型 │ 指派给 │ 预计 │ 截止   │  ✕      │          │
│ │ 1│ 方案设计     │ 设计 │ 我    │ 3h  │ 10-28 │         │          │
│ │ 2│ 核心功能开发  │ 开发 │ 我    │ 6h  │ 10-30 │         │          │
│ │ 3│ 联调与自测    │ 开发 │ 我    │ 3h  │ 10-31 │         │          │
│ │ 4│ 测试用例与验证 │ 测试 │ 张三  │ 2h  │ 11-01 │         │          │
│ └──┴────────────┴────┴──────┴─────┴──────┴────────┘          │
│ [＋ 添加一行]                          [取消]  [创建 4 个任务] │
└───────────────────────────────────────────────────────────────┘
```

- **执行**：下拉里"收藏的执行 / 默认执行"排在前面；已关联该需求的执行标"已关联"。选了**还没关联该需求**的执行时提示"创建任务前会先把需求关联到这个执行"（是否能自动关联、有什么副作用以抓包为准；不能自动关联就提示去禅道关联并禁用创建）。
- **每行字段**：标题（必填）、类型（设计 / 开发 / 测试 / 研究 / 讨论 / 界面 / 其它，默认开发）、指派给（默认我，可选团队成员）、预计工时（小时，可空）、截止日期（可空）、描述（折叠，默认带需求标题和链接）。优先级继承需求的优先级。
- **AI 拆分建议**：把需求的描述和验收标准交给 AI，得到 3~6 条任务（标题、类型、建议工时）填进表格，**用户可任意改**。没配 AI 时给一套通用模板行（设计 / 开发 / 联调 / 测试）。AI 的约束：只拆需求里明确要做的事、不编造需求之外的功能、工时给整数小时。
- **创建**：一次提交，逐个创建（或批量接口，以抓包为准）。结果显示成功 / 失败各几条，失败的保留在表格里可改了重试；成功的任务带禅道链接。
- 创建完成后：自动把新任务同步到本地任务看板，需求详情里的"已有任务"刷新。

### 2.3 规则
- 同一次不允许两行标题完全相同；标题去首尾空格。
- 预计工时 ≥ 0，支持 0.5 步长；截止日期不能早于今天。
- 创建任务**不改变需求自身的状态**（需求阶段由禅道按任务进度自己推进，抓包时记录变化）。

## 3. Bug 转任务

### 3.1 入口
- Bug 详情弹窗头部、Bug 卡片的操作区：「转任务」。
- 只对**未解决**的 Bug 可用（未确认 / 已确认）；已解决 / 已关闭的置灰。
- **已转过任务**的 Bug：按钮变成徽标「已转任务 #T」，点击打开那个任务，不再允许重复转。

### 3.2 弹窗

```
┌ Bug 转任务 · #88 登录超时 ──────────────────────────────┐
│ 创建到执行：[ 2026 年工作日志记录 ▾ ]                      │
│ 任务标题：[ 【Bug#88】登录超时                        ]    │
│ 类型：[ 开发 ▾ ]  指派给：[ 我 ▾ ]  优先级：[ 2 ▾ ]         │
│ 预计：[ 2 ]h   截止：[ 2026-10-27 ]                       │
│ 描述：[ 重现步骤…（自动带入 Bug 的步骤，可改）+ Bug 链接 ]    │
│ ☑ 转任务后把 Bug 指派给任务负责人（以抓包为准）             │
│                                  [取消]  [转为任务]       │
└──────────────────────────────────────────────────────────┘
```

- **预填**：标题 =「【Bug#编号】+ Bug 标题」（前缀可去掉）；描述 = Bug 的重现步骤（去掉 HTML 噪音）+ Bug 的禅道链接；优先级由 Bug 严重程度映射（致命→1、严重→2、一般→3、提示→4）；指派给默认我，也可选 Bug 当前的指派人。
- **执行**：同样"收藏 / 默认执行"优先；Bug 所属产品与执行所属项目要匹配，不匹配的执行置灰并说明（以抓包为准）。
- **创建后**：Bug 与任务在禅道里互相关联；Bug 的状态怎么变（是否保持原状、是否标记"已转任务"）以抓包为准，界面照禅道的结果显示，不自己改。
- 新任务同步到本地任务看板。

## 4. 数据与接口（草案，抓包后定稿）

| 接口 | 说明 |
|---|---|
| `GET /api/stories/:id/tasks` | 这个需求下已有的任务（来自需求详情 / 执行任务列表） |
| `GET /api/stories/:id/execution-options` | 可选执行及是否已关联该需求 |
| `POST /api/stories/:id/tasks/suggest` | AI 拆分建议（只生成，不写任何东西） |
| `POST /api/stories/:id/tasks` | 创建 `{executionId, tasks:[{name,type,assignedTo,estimate,deadline,desc,pri}]}`，返回逐个的成功 / 失败；创建后触发本地同步 |
| `POST /api/bugs/:id/to-task` | `{executionId, name, type, assignedTo, pri, estimate, deadline, desc}`；创建后触发本地同步 |

- 复用：`createTask`（`task-create-{执行}`，已有的字段映射）、`syncMyTasks` / `syncMyBugs`（把新任务 / 新状态拉回本地）、执行收藏与默认执行（`executionManager`）、团队成员列表。
- 创建任务时 `story` 字段（需求拆任务）和 Bug 关联字段（Bug 转任务）是新增的，**具体字段名与请求格式以抓包为准**，不凭文档盲写。
- 前端不存任何东西（延续"数据以后端 / 禅道为准"）。

## 5. 错误与边界

| 情况 | 处理 |
|---|---|
| 执行里没有关联这个需求 | 提示并尝试关联（能不能由接口完成以抓包为准），失败则禁用创建并说明 |
| 批量创建中途失败 | 已成功的保留（不回滚），失败的行留在表格里标原因，可重试；全部结果在结果区列出 |
| 登录失效 | 立刻停止，已创建的保留并告知 |
| Bug 已被别人转过任务 | 打开弹窗时重读 Bug，发现已转则显示徽标并阻止重复 |
| AI 不可用 / 返回不合格 | 退回通用模板行，提示去配置 AI |
| 同名任务已存在于该执行 | 允许（禅道允许重名），但标题相同的行在同一次里要先改 |

## 6. 与现有功能的联动

- **任务看板**：新任务自动出现；任务卡片上若有关联需求 / Bug，显示小标签「需求 #172」/「Bug #88」，点击跳转。
- **待办页**：需求里"指派给我 / 评审中"那一卡不变；任务卡里新建的任务照常出现。
- **工作日历**：新任务可直接记工时。
- **报告**：日报 / 周报里任务关联的需求 / Bug 可作为上下文（可选，后续）。

## 8. 验收标准

1. 需求详情有「拆任务」；能选执行、增删改行、看到合计；AI 建议填表后可改；没配 AI 有模板。
2. 创建后禅道里每个任务都关联到该需求，字段与表格一致；本地任务看板马上出现。
3. 同一个需求再次打开拆任务，顶部能看到已有任务。
4. Bug 详情 / 卡片有「转任务」；预填正确；创建后禅道里 Bug 与任务互相关联，Bug 显示「已转任务 #T」，不能重复转。
5. 批量创建部分失败时，成功的保留、失败的可重试，且不会重复创建已成功的。
6. 全程不改需求 / Bug 自身的评审、解决流程。

## 9. 分阶段

| 阶段 | 内容 |
|---|---|
| **P0** | **Bug 转任务**（单个任务，流程最短）：弹窗、预填、创建、关联、同步、已转徽标 |
| **P1** | **需求拆任务**：执行选择与关联、多行表格、批量创建、结果与重试、已有任务展示 |
| **P2** | AI 拆分建议；任务卡片上的"来源需求 / Bug"小标签与跳转；报告里带关联上下文 |
