# 「首次使用引导 + 更新说明」PRD

> 实现时的补充：引导共 4 步——① 连接禅道 ② 配置 AI ③ 报告与推送时间（早间提醒 / 日报生成并推送的钟点，0~23 点）④ 节假日（法定节假日 + 调休日）。下文 §3 只写了前两步，第 3、4 步用的是设置页同一套字段（`morningHour` / `eveningHour` / `workHolidays` / `workMakeup`），同一个 `POST /api/config` 保存，后端校验失败的原因直接显示在卡片里。

> 状态：**P0、P1 已实现**（2026-10-24）。按产品负责人意见：只引导配置、只在首次安装显示一次、更新后单独弹更新内容；引导由原来的两步扩成四步（增加「报告与推送时间」「节假日」）。老用户升级不补弹；更新说明一次最多 3 个版本；「以后再说」后不再出现（设置 → 关于 可重新查看）。
> 背景：安装器和首次登录卡片已经有了（未登录时自动弹登录卡片，可「导入旧配置」「稍后再说」）。缺的是把「配禅道」和「配 AI」串成一次完整的首次体验，以及更新之后告诉用户改了什么。

---

## 1. 范围与原则

**做**

1. **首次安装引导**：两步——① 连接禅道 ② 配置 AI。只在扩展第一次安装后显示一次。
2. **更新说明**：自动更新（或手动更新）完成后，用户第一次打开新标签页时，显示这次更新的内容，每个版本只显示一次。

**不做**

- 不涉及任何禅道业务（工时、缺填、任务、节假日等都不进引导）。
- 不做常驻清单、不做逾期重复提醒；用户跳过就是跳过，之后只能自己去设置页，或在设置里点「重新查看新手引导」。
- 不新增必填项：禅道和 AI 都可以跳过，本地模式可用，不配 AI 走本地规则解析。

**原则**：不拦路（随时可关）；不重复造轮子（复用现有登录卡片、AI 配置和「测试连接」）；前端不存业务数据（只存「引导看过 / 更新说明看过哪个版本」两个界面偏好）。

---

## 2. 什么时候算「第一次安装」

用 `chrome.storage.local`（扩展自己的存储，更新、重载都不会丢；比页面的 `localStorage` 可靠）记一个键：

```
waOnboarding = { introDone: boolean, seenVersion: "1.5.2" }
```

| 情形 | 判定 | 行为 |
|---|---|---|
| 全新安装 | `onInstalled` 的 `reason === 'install'` | 写 `introDone=false`，`seenVersion=当前版本`；下次打开新标签页显示首次引导 |
| 升级到带引导的版本（老用户） | `reason === 'update'` 且还没有 `waOnboarding` | 静默写 `introDone=true`、`seenVersion=当前版本`，**不显示引导，也不补弹这一版的更新说明** |
| 之后每次更新 | 当前版本 > `seenVersion` | 显示更新说明（见 §4） |
| 在设置里「重置为首次使用」 | 已有的调试功能 | 同时把 `introDone` 置为 `false`，方便复测 |
| 卸载重装 | 存储被清空，等同全新安装 | 显示引导 |

> 导入旧配置（换电脑）：导入成功后，禅道与 AI 都恢复了，直接把 `introDone` 置 `true`，不再引导。

## 3. 首次安装引导（两步）

不另做一套全屏向导，而是**给现有的登录卡片加步骤条，并接上 AI 这一步**，这样未登录自动弹窗的行为保持不变。

### 步骤 1/2：连接禅道

就是现有的登录卡片（自动弹出），只是顶部多一行 `第 1 步 / 共 2 步`，并在卡片底部保留已有的「导入旧配置」「稍后再说」。

- 登录成功 → 进入步骤 2。
- 点「稍后再说」（进入本地模式）→ 也进入步骤 2（AI 与禅道无关）。
- 点「导入旧配置」成功 → 引导直接结束（§2 末）。

### 步骤 2/2：配置 AI

复用现有的 AI 配置（`设置 → AI 配置` 的同一套字段），以小卡片形式出现：

```
第 2 步 / 共 2 步
配置 AI（可选）
新建任务、日报周报会用到。不配也能用，会改用本地规则。

接口地址  [ https://open.bigmodel.cn/api/paas/v4/ ]
API Key   [ ****************************** ]
模型      [ 自动推荐 ▾ ]            [测试连接]
✓ 连接成功，推荐模型 glm-x（约 3 秒）

[ 以后再说 ]                         [ 完成 ]
```

- 「测试连接」用现有的 `POST /api/ai/test`；通过后才允许点「完成」保存，不通过就提示原因（Key 错误 / 地址不通 / 超时），可改了再试，也可以「以后再说」。
- 「完成」保存配置并关闭；「以后再说」直接关闭，都视为引导已看过。
- 保存成功后提示一句「之后可在 设置 → AI 配置 修改」。

### 结束

两步走完或中途关闭，一律 `introDone=true`，之后不再显示。结尾不弹额外页面，只在右下角给一条一次性提示：「设置里可以随时重新查看新手引导」。

### 异常

| 场景 | 处理 |
|---|---|
| 后端没起来 | 现有逻辑会先尝试拉起；仍失败则登录卡片给出现有的错误提示，引导停在步骤 1，不标记完成（下次打开还会出现） |
| 禅道连不上（内网） | 沿用登录卡片的真实登录校验报错，补一句「是否需要先连公司网络 / VPN」 |
| 用户在引导途中关掉页面 | 未走完不标记；下次打开新标签页从步骤 1 重新来（已配好的步骤会自动判完成并跳过：已登录跳过 1，已配 AI 则直接结束） |
| 用户已经自己配好了禅道和 AI | 打开时检测到两者都已配置，直接标记完成，不弹 |

## 4. 更新说明

**触发**：新标签页加载时，读 `seenVersion`，若小于当前扩展版本且不是首次安装，则向后端取这段版本区间的更新内容并弹出；用户关闭后把 `seenVersion` 写成当前版本。

自动更新会重载扩展并刷新已打开的新标签页（已有逻辑），所以用户感知到的就是「更新完，页面刷新后看到说明」。

**内容来源**：仓库已有 `CHANGELOG.md`。

- 打包时把 `CHANGELOG.md` 一起放进安装包（`scripts/build-package.mjs` 加一行拷贝）。
- 后端新增 `GET /api/changelog?since=1.5.1`，解析 `## 版本号（日期）` 分段，返回 `since` 之后（不含）到当前版本的各版本条目，按版本倒序。
- 插件不内置更新内容，避免和后端不同步。取不到（旧后端、接口失败）就静默不弹，并且**不**写 `seenVersion`，下次再试。

**展示**：

```
🎉 已更新到 1.5.2
修复
 · 任务页左上角的日历热度没有体现补过的工时 …
 · 自动更新「立即更新」找不到新版本 …
                       [ 查看完整更新记录 ]   [ 知道了 ]
```

- 一次跨多个版本（例如离线几周）：合并展示，最多 3 个版本，更早的折叠成「还有 N 个版本，查看完整更新记录」。
- 「查看完整更新记录」：设置页新增「更新记录」入口，列出全部版本。
- 条目只显示「新增」「修复」「变更」，不显示内部排障细节：对 `CHANGELOG.md` 现有写法不做改写，保持原文。
- 弹窗不遮挡登录卡片：若同时需要登录（`invalid`），先登录，更新说明延后到下一次打开。
- 手动「重新安装」到同一版本：版本没变，不弹。

## 5. 实现范围

**后端**
- `GET /api/changelog?since=`（解析 `CHANGELOG.md`，带测试）。
- `build-package.mjs`：打包带上 `CHANGELOG.md`；开发版（仓库运行）直接读仓库里的文件。

**扩展**
- `background.js` 的 `onInstalled`（已有，约 865 行）：按 §2 写 `waOnboarding`。
- `extension/account.js`：登录卡片加步骤条；登录 / 跳过后进入 AI 步骤（把现有的 `showAiHint` 升级成步骤 2 卡片，去掉 `waAiHintPending` 的 localStorage 标记）。
- 新增 `extension/onboarding.js`：判定是否显示引导 / 更新说明，渲染更新说明弹窗。
- 设置页：新增「重新查看新手引导」「更新记录」。

**测试**（沿用现有 jsdom 套件的写法）
- 全新安装显示引导；老用户升级不显示；两步各自的跳过 / 完成路径都标记 `introDone`。
- 更新说明：版本升高才弹；同版本不弹；取不到内容不写 `seenVersion`；跨版本合并与折叠；与登录卡片的先后。
- `/api/changelog` 解析：有 / 无日期、「未发布」段、非法 `since`。

**不做**：内置法定节假日表；任何使用统计上传；引导里的业务操作。
