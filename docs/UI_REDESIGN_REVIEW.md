# 工作助手 · UI 评审与改版方案

> 评审对象：`extension/newtab.css`（主界面）+ `extension/settings.css`（设置弹窗）
> 风格基准：浅色极简 + 卡片式布局 + 克制配色 + 数据可视化（B 端工作台）
> 评审人：像素君 · UI Designer ｜ 日期：2026-10-22

---

## 一、风格基准回顾（目标状态）

一句话定位：**浅色极简、卡片式布局、配色克制、信息层级清晰的专业 B 端工作台。**

| 维度 | 目标标准 |
|---|---|
| 配色 | ≤3 个主色 + 中性色；重点信息靠层级而非颜色抢夺 |
| 卡片 | Card Layout 统一；圆角一致；阴影轻；用留白代替分割线 |
| 间距 | 8 / 16 / 24 设计体系，卡片间留足呼吸感 |
| 层级 | 核心数据 → 趋势分析 → 明细列表 → 辅助信息，视线自然流动 |
| 图表 | 折线=趋势、柱状=对比、环形=占比、表格=明细；单页 ≤3 类 |

## 二、现有 UI 评审结论

### 2.1 核心问题：两套视觉语言割裂

| 区域 | 当前设计语言 | 主色 |
|---|---|---|
| 主界面 `newtab.css` | 旧 · 靛蓝冷色系 | `#6366f1`（Indigo） |
| 设置弹窗 `settings.css` | 新 · 「墨台」暖色系 | `#0F766E`（青瓷绿） |

**结论：** 项目已经有一份成熟、落地度很高的「墨台」设计系统（`docs/UI_DESIGN_PROPOSAL.html`），且设置页已完成迁移；但主界面（看板、日历、任务卡片、Bug 卡片）仍停留在旧靛蓝色系，导致同一产品在「设置」与「主界面」之间风格跳变，专业度受损。

### 2.2 与风格基准的逐项对照（主界面 newtab.css）

| 检查项 | 现状 | 评价 |
|---|---|---|
| 配色克制 | 主色 `#6366f1` + 散落硬编码色 | ⚠️ 问题 |
| 中性色统一 | `#f8fafc/#1e293b/#64748b/#94a3b8`（冷灰） | ⚠️ 与暖色系冲突 |
| 卡片圆角 | `6/10/16/20px` 四级 | ⚠️ 层级过多 |
| 阴影 | 三层阴影尚可 | ✅ 基本达标 |
| 间距体系 | 未按 8pt 严格统一 | ⚠️ 需规范 |
| 数据可视化 | 仅 GitHub 风格日历热力 + 进度条 | ⚠️ 缺趋势图 |

### 2.3 散落硬编码颜色（需清理）

主界面 `newtab.css` 中存在大量未纳入设计令牌的颜色，是「配色不克制」的直接来源：

- `#4CAF50`（Material 绿）—— Bug ID 链接、多选组件选中态（8 处）
- `#667eea → #764ba2` 渐变 —— 多选标签胶囊
- `#10b981` / `#059669` —— 禅道同步按钮
- `#8e44ad` / `#d35400` / `#16a085` —— 测试按钮
- `#dc2626 / #f97316 / #fbbf24 / #9ca3af` —— Bug 严重程度

**这些颜色相互独立、来源各异（Material / Tailwind / 自定义），是当前界面「看起来不够高级」的根源。**

## 三、改版方案

### 3.1 核心策略：三件事

1. **统一主界面到「墨台」暖色系** —— 消除主界面与设置页的割裂。
2. **收敛颜色到 ≤3 主色 + 中性色** —— 清理所有硬编码色，全部令牌化。
3. **收紧卡片/间距/圆角规范** —— 对齐 8pt 体系，用留白代替分割线。

### 3.2 目标设计令牌（主界面 `:root` 迁移）

```css
:root {
  /* —— 主色（青瓷绿，与设置页一致） —— */
  --accent: #0F766E;
  --accent-hover: #115E59;
  --accent-soft-bg: #E6F4F1;
  --accent-soft-ink: #0F766E;

  /* —— 暖中性色 —— */
  --ink: #2A2724;          /* 主文字 */
  --text-2: #5C574E;       /* 次级文字 */
  --text-muted: #766F64;   /* 弱化文字 */
  --bg-base: #FAF9F6;      /* 页面底 */
  --bg-surface: #FFFFFF;   /* 卡片面 */
  --bg-sunken: #F3F1EC;    /* 凹陷区 / 输入框底 */
  --border: #E6E2D9;       /* 描边 */
  --border-strong: #8C877D;

  /* —— 语义色（克制，仅此三类） —— */
  --success: #15803D;      /* 完成 / 增长 */
  --warning: #B45309;      /* 进行中 / 待处理 */
  --danger: #B91C1C;       /* 待办 / 严重 */

  /* —— 圆角收敛为三级 —— */
  --radius-control: 6px;
  --radius-card: 10px;
  --radius-modal: 14px;

  /* —— 阴影更轻，不抢戏 —— */
  --shadow-sm: 0 1px 2px rgba(42, 39, 36, 0.05);
  --shadow-md: 0 4px 16px -4px rgba(42, 39, 36, 0.08), 0 1px 3px rgba(42, 39, 36, 0.04);
  --shadow-lg: 0 24px 48px -12px rgba(42, 39, 36, 0.18), 0 2px 6px rgba(42, 39, 36, 0.05);
}
```

> 旧变量名（`--primary` / `--text-primary` / `--border` 等）在迁移期做一次映射，保证历史组件不崩、JS 不动，与 `settings.css` 的做法一致。

### 3.3 组件级改造清单

| 组件 | 现状问题 | 改版动作 |
|---|---|---|
| 日历热力图 | GitHub 绿色阶，与整体色系割裂 | 换成青瓷绿渐变阶（`#E6F4F1 → #0F766E`） |
| 任务卡片 | 左侧 3px 灰色条 + 冷灰描边 | 左侧条改用语义色（待办=红 / 进行中=橙 / 完成=绿），描边改暖灰 |
| 进度条 | `indigo→green` 渐变 | 改 `accent` 纯色或 `accent→success` 克制渐变 |
| Bug 严重度标签 | `dc2626/f97316/fbbf24` 四色 | 收敛为 danger/warning + 中性灰三档 |
| Bug ID 链接 | Material `#4CAF50` | 统一为 `--accent` |
| 多选标签胶囊 | `#667eea→#764ba2` 渐变 | 改 `--accent-soft-bg` + `--accent-soft-ink` 浅底深字 |
| 禅道同步按钮 | `#10b981` | 统一为 `--success` |
| Tab 切换 | 下划线 + 主色高亮 | 保留，颜色对齐 `--accent` |
| 测试按钮 | 四色糖果色 | 仅调试态保留，收敛为中性灰描边 |

### 3.4 信息层级强化（对齐文章「四层结构」）

当前主界面已有「看板 → 列 → 卡片」的雏形，但缺少第一层的**核心数据概览**。建议在 Tab 上方增加一行 **KPI 概览条**（本周完成 / 本月完成 / 连续天数 / 今日工时），用克制的中性色 + 单一强调色呈现，让用户「一眼看到今天该关注什么」，同时强化趋势可视化：

- 当前仅有日历热力图与进度条，缺少**趋势折线/柱状图**；
- 建议「历史报告」弹窗内补充趋势图（折线=完成趋势），而非堆在首页。

### 3.5 落地顺序（低风险渐进式）

1. **Phase 1 — 令牌迁移**：在 `newtab.css` 的 `:root` 落地新令牌 + 旧变量映射（纯 CSS，零 JS 改动）。
2. **Phase 2 — 颜色收敛**：清理全部硬编码色，替换为令牌。
3. **Phase 3 — 组件细化**：卡片/圆角/阴影/标签胶囊逐项对齐。
4. **Phase 4 — 信息层级**：补 KPI 概览条与趋势图（需少量 JS/HTML）。

---

## 四、一句话总结

> 你不需要「重画」界面，而是把已经做得很好的「墨台」暖色系统**从设置页推广到整个主界面**，同时把散落的硬编码色收敛回 3 个主色 + 中性色 —— 这正是那篇文章强调的「颜色越少、数据越突出」。
