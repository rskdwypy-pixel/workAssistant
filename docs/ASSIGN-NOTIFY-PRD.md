# 新指派提醒 PRD

> 状态：1.10.0 实现。范围（已确认）：**只提醒「新指派给我的」任务 / Bug / 需求**；通道含**系统通知、Webhook 推送、插件里的未读列表**。

## 1. 目标

别人把任务、Bug、需求指派给我时，几分钟内就知道——不用一直盯着禅道。

**不做（本期）：** 评论、状态变化（解决 / 关闭 / 激活）、别人在我创建的对象上的操作；提醒别人。这些以后可以在同一个检测框架上加。

## 2. 调研结论：为什么不用禅道的「动态」或站内消息

在新旧两版禅道（18.3 / 22.3）上，用管理员账号造数据、再以本人身份读取，逐条实测：

| 来源 | 结论 |
|---|---|
| 禅道站内消息（`message-ajaxGetMessage`） | **不可用**：管理员在「消息设置」里勾选了各事件的站内消息，但 admin 指派给我之后消息箱仍是 0 条，通道本身没打开；开它要改管理员设置 |
| 动态（`company-dynamic`）里的 `assigned` 记录 | **不全**：新版「新建时直接指派」有、旧版只有 `opened`；**在编辑表单里改指派人，两个版本都只记 `edited`**；只有点「指派」按钮才一定有 `assigned` |
| 动态里别人的操作 | 能看到（新版 941 条别人的非登录操作），但登录记录很多、量大 |
| **「我的」列表**（`my-task/bug/story-assignedTo`） | **权威**：谁、怎么指派的都会体现，新旧版本一致，每次 3 个请求 |

## 3. 方案

```
每 5 分钟：读「指派给我」的任务 / Bug / 需求 3 个列表（复用现有登录会话）
          └─ 和上次看到的 ID 集合比 → 新出现的 = 新指派给我的
              ├─ 已完成 / 已关闭 / 已解决的不提醒
              ├─ 读该对象详情里的操作历史，找「指派时间」附近的操作 → 得到是谁指派的
              ├─ 是我自己指派给自己的 → 不提醒
              └─ 其余：记入未读列表 + 系统通知 + Webhook（多条合并成一条）
```

- **首次启用 / 换了禅道地址或账号**：只建基线，不把存量全弹出来；换账号时旧通知记录一并清掉。
- **改派走又被指派回来**：算新指派（集合里先消失再出现）。
- **某一类读取失败**：这一轮跳过，保持上次记录，恢复后不会误报也不会漏报。
- **登录次数**：只复用现有会话，每 5 分钟 3 个请求，不会产生登录动态；还能让旧版禅道 24 分钟的空闲过期时间不再生效。

## 4. 界面

- **右上角铃铛**（登录后显示）：红色角标 = 未读数。点开是列表：`杨凯 指派了任务 #3` / 标题 / `2 小时前 · 截止 11-05 · P2`；未读有红点；点一条 = 标记已读并在禅道里打开；「全部已读」「立即检查」「提醒设置」。
- **设置 → 通知推送 → 新指派提醒**（修改即时生效）：总开关、系统通知、Webhook 推送、「发送测试」「立即检查」。Webhook 沿用下面已有的地址配置；没配置时给提示。

## 5. 接口

| 接口 | 说明 |
|---|---|
| `GET/POST /api/notify/settings` | `{enabled, system, webhook}`（只认这三个布尔值），GET 另带 `webhookConfigured` |
| `GET /api/notifications` | 未读列表 `{items, unread}`，新收到的在前，最多 100 条 |
| `POST /api/notifications/read` | `{ids: [...]}` 或 `{ids: 'all'}` |
| `POST /api/notifications/check` | 立即检查一次 |
| `POST /api/notifications/test` | 发一条测试提醒，返回系统通知 / Webhook 各自是否发出 |

数据：`data/notify-settings.json`、`data/notify-state.json`（上次看到的 ID 集合）、`data/notifications.json`。换账号 / 重置时随本地数据一起清。

## 6. 验收

1. 首次检查只建基线，存量不提醒。
2. 别人新指派给我的任务 / Bug / 需求：提醒，写明操作人姓名、标题、截止日、链接。
3. 我自己建的、指派给自己的：不提醒。
4. 新建时指派、改派、在编辑里改指派人，新旧两版禅道都能抓到（真实环境实测）。
5. 多条同时出现合并成一条推送；系统通知和 Webhook 分别可关；没配 Webhook 不推。
6. 换地址 / 换账号后重新建基线，旧通知清空。
7. 铃铛：登录后才显示；未读数；点一条标记已读并打开；全部已读；Esc / 点外面关闭。
