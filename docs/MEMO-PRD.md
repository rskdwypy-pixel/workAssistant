# 「备忘录」PRD：插件内的个人速记本（含加密同步）

> 状态：设计稿（待实现）
> 作者：产品 + 研发（Claude 协助）
> 日期：2026-11-11

在「文档」与「工作日历」之间新增「🗒️ 备忘录」标签页。定位是**个人速记本**：随手记、随手查、多端通过禅道加密同步。

## 1. 目标与非目标

**一句话**：打开新标签页就能记、能翻、能搜的个人备忘录，和任务/需求/文档这些"工作对象"平级但互不干扰。

**目标**
- 快速记录：标题 + 正文（Markdown），3 秒记一条。
- 整理：置顶、标签分类、全文搜索。
- 加密同步：每条备忘录对应禅道文档库中的一个文档，标题明文、正文加密，多端通过禅道同步。

**非目标（本期不做）**
- 不做团队共享 / 协作（禅道没有备忘录概念，硬塞只会碎）。
- 不做富文本所见即所得编辑器（沿用项目既有决策，见 DOC-FEATURE-PRD §1）。
- 不做日历 / 提醒类（那是工作日历和提醒的活）。

## 2. 与现有功能的关系

| 功能 | 区别 |
|---|---|
| **文档**（📁） | 禅道里的团队资产，实时以禅道为准；备忘录是**个人数据加密后存自己的文档库**，不展示在文档页 |
| **待办 / 任务**（📌📋） | 结构化、可指派、可同步；备忘录是自由文本，不进任务流 |
| **工作日历**（📅） | 工时与报告；备忘录是"想法/备忘/草稿纸" |

**一句话定位**：待办记"要做什么"，任务记"正在做什么"，备忘录记"想到什么"。

## 3. 信息架构与交互

```
┌───────────────────────────────────────────────────┐
│ 🗒️ 备忘录              [🔍 搜索]        [＋ 新建] │
│ ┌──────────────────────────────────────────────┐  │
│ │ 📌 周会要点                      #工作 #会议  │  │
│ │ 1. Q4 排期…（Markdown 渲染，前 2 行预览）     │  │
│ │ 2. …                                         │  │
│ ├──────────────────────────────────────────────┤  │
│ │ 📌 取快递                           #生活     │  │
│ │ …                                            │  │
│ ├──────────────────────────────────────────────┤  │
│ │ 📌 重构 zentaoService 的想法      #工作 ▸任务 │  │
│ │ …                           [在禅道打开 ↗]  │  │
│ └──────────────────────────────────────────────┘  │
│ 已置顶 2 · 共 42 条          [全部 | #工作 | #生活] │
│ 同步：🔒 已启用 → 个人库          [同步设置]        │
│ ⚠️ 2 条待同步（上次同步失败）  [立即同步]          │
└───────────────────────────────────────────────────┘
```

- **列表**：卡片式，标题 + 正文前两行预览 + 标签 + 更新时间；置顶卡片有明显标识。
- **新建 / 编辑**：弹窗（沿用项目既有弹窗规范），标题必填、正文可选、标签可多个。
- **删除**：弹确认框 → 删除禅道文档（放回收站）+ 本地移除。
- **搜索**：标题 + 正文 + 标签全文匹配，前端实时过滤。
- **同步状态条**：页脚显示同步状态（已同步 / 待同步 N 条 / 同步中 / 同步失败 / 未启用），点击进入同步设置。
- **待同步标记**：编辑后未成功上传的备忘录，卡片上有"待同步"角标，下次同步自动重试。

## 4. 数据模型（data/memo.json）

本地存储，沿用 `src/utils/storage.js` 的原子写 + 备份机制：

```json
{
  "version": "1.0",
  "lastUpdated": "ISO 时间",
  "memos": [
    {
      "id": "uuid",
      "docId": "1234",
      "title": "周会要点",
      "content": "Markdown 文本",
      "tags": ["工作", "会议"],
      "pinned": true,
      "refs": [{ "type": "task", "id": "496", "title": "重构 zentaoService" }],
      "createdAt": "ISO",
      "updatedAt": "ISO",
      "syncDirty": false
    }
  ],
  "syncState": {
    "enabled": true,
    "libId": "185",
    "libName": "个人空间",
    "lastSyncAt": "ISO",
    "lastSyncResult": "ok | partial | failed"
  }
}
```

- **排序**：置顶优先，其次 `updatedAt` 倒序。
- **并发安全**：沿用 `updateTasks` 的 Promise 锁模式（`updateMemos`）。
- **`docId`**：对应禅道文档 ID（同步后写入，新建时为空）。
- **`syncDirty`**：本地有更新但未成功上传到禅道（同步失败时保留，下次自动重试）。
- **`syncState`**：同步配置与最后同步状态，换机后从后端读回。
- **删除策略**：以禅道为准。插件删除 = 调禅道删除接口 + 本地移除；禅道里手动删文档 = 下次同步时本地自动移除（拉不到就删）。

## 5. 加密同步设计

### 5.1 口令：禅道用户 ID

**口令 = 当前登录用户的禅道用户 ID**（`my-profile.json` → `user.id`）。

- 无需设置、不会忘记：登录禅道后自动获取，写入后端缓存。
- 天然隔离：每个人的 ID 不同，只能用自己的 ID 解密自己的备忘录。
- 换机 / 换浏览器：登录同一禅道账号 → 拿到同一 ID → 自动解密。

> **安全边界（如实说明）**：禅道用户 ID 在禅道内可见（用户列表接口），所以这不是密码学意义上的强加密——它**防止禅道上明文直读**（满足需求），但如果有人知道用户 ID，理论上可以用该 ID 派生密钥解密。如果未来需要更强保护，可在用户 ID 基础上追加可选的额外口令（scrypt 混合），但本期不做。

### 5.2 载体：禅道文档库（每条备忘录 = 一个文档）

**载体是用户选定的禅道文档库（lib），每条备忘录对应库中的一个文档。**

| 载体元素 | 内容 | 保密性 |
|---|---|---|
| **文档标题** | = 备忘录标题 | **明文**（用户确认不保密） |
| **文档正文** | 加密 JSON（含正文 Markdown、标签、置顶、关联引用、updatedAt 等） | **密文**（AES-256-GCM） |

文档放在选定文档库的根目录（module 为空），不需要用户选子目录。

> **设计理由**：
> - 标题明文 → 禅道文档列表直接可见备忘录标题，像原生备忘录列表
> - 正文加密 → 禅道上看不到内容，满足"不想明文看到"
> - 每条备忘录一个文档 → 天然支持逐条 CRUD，不需要整包加密/合并
> - 删除以禅道为准 → 不需要 tombstone，禅道删了本地就删
> - 多用户隔离 → 各自选自己的库，互不干扰

### 5.3 加密算法（复用 configTransfer.js）

| 组件 | 说明 |
|---|---|
| KDF | scrypt（N=32768, r=8, p=1），口令 = `String(user.id)`，salt 随机生成 |
| 加密 | AES-256-GCM，iv 随机生成（12 字节） |
| 完整性 | GCM auth tag 防篡改：密文被改 → 解密报错 |
| salt / iv | 随密文一起存文档正文（公开无妨，安全性来自口令） |

复用 `configTransfer.js` 的 `deriveKey` + `createCipheriv('aes-256-gcm')` 逻辑，新建 `src/utils/memoCrypto.js` 统一封装。

### 5.4 文档正文格式（加密前明文 / 加密后存文档正文）

加密前的明文结构（JSON）：

```json
{
  "v": 1,
  "title": "周会要点",
  "content": "Markdown 正文",
  "tags": ["工作", "会议"],
  "pinned": true,
  "refs": [{ "type": "task", "id": "496", "title": "重构 zentaoService" }],
  "updatedAt": "ISO 时间",
  "createdAt": "ISO 时间"
}
```

加密后存文档正文（base64）：

```
{
  "userId": 123,
  "salt": "base64",
  "iv": "base64",
  "tag": "base64",
  "updatedAt": "ISO",
  "data": "base64(AES-256-GCM(JSON))"
}
```

> 注：`title` 明文存文档标题，正文里也存一份（加密），这样改标题时只需要改文档标题，正文里的 title 跟着一起改。或者正文里不存 title（标题就是文档标题），更简洁。**采用后者**：正文明文里不存 title，标题以文档标题为准。

### 5.5 同步流程

```
本地编辑 ──加密──→ 更新禅道文档 ──┐
                                   │ 多端通过禅道同步
禅道文档列表变化 ──拉取──→ 解密 ──→ 合并本地 ──→ 写回 data/memo.json
```

**上行（本地 → 禅道）**：
1. 编辑后：`syncDirty = true`，尝试立即上传
2. 上传：加密正文 → 更新禅道文档（有 docId 则 update，无则 create）
3. 成功：`syncDirty = false`，更新本地 `updatedAt`
4. 失败：`syncDirty` 保留，下次同步自动重试

**下行（禅道 → 本地）**：
1. 列出文档库全部文档（复用 `docService.listDocs`，按 libId 过滤）
2. 逐条解密正文（用当前用户 ID）
3. **合并到本地**（见 5.6）
4. 写回 `data/memo.json`

**删除同步**：
- 插件删除：调禅道删除接口（放回收站）+ 本地移除
- 禅道手动删：下次同步拉不到该文档 → 本地自动移除（以禅道为准）
- 误删恢复：从禅道回收站恢复文档 → 下次同步自动回来

**同步时机**：
- 打开备忘录页时拉取一次（先画缓存、再刷新，复用 auto-sync 套路）
- 编辑后立即上传（防丢）
- 开着时每 5 分钟同步一次（复用 auto-sync 定时器）
- 手动「立即同步」按钮

### 5.6 冲突策略：条目级合并

每条备忘录独立同步，不存在"整包冲突"。同一条备忘录两端同时编辑时：

| 场景 | 处理 |
|---|---|
| 两端各改不同备忘录 | 各自保留，互不影响 |
| 两端改了同一条 | 按 `updatedAt` 取较新者 |
| 一端删除、另一端编辑同一条 | 删除优先（禅道里没文档了，编辑内容拉不到，本地移除） |

合并逻辑（下行时）：
1. 拉取远端文档列表 → 解密 → 得到远端 memos（docId → memo）
2. 本地 memos 构建 map（docId → memo）
3. 远端每条：本地有同 docId → 取 `updatedAt` 较新者；无同 docId → 加入
4. 本地每条：远端列表中没有其 docId → 本地移除（以禅道为准）
5. 写回本地

### 5.7 文档库配置

首次启用同步时的引导流程：

1. 备忘录页点「同步设置」→ 提示"启用加密同步"
2. **弹窗列表选择文档库**：后端列出当前账号可见的文档库（复用 `docService.listLibs`），前端展示库名 + 空间标签
3. 用户点选一个库（建议建一个专用库，设私有 ACL）
4. 配置写入 `syncState`（libId + libName），换机后自动恢复
5. 首次同步：本地有备忘录 → 在选定库中创建文档；本地为空 → 等待用户新建

> 建议：选择或创建一个专用文档库（如"个人空间"），设为私有 ACL；标题是备忘录标题（明文）；正文是密文。

### 5.8 安全边界汇总

| 威胁 | 防护 |
|---|---|
| 禅道上明文可见 | ✅ 正文 AES-256-GCM 加密，只存密文 |
| 标题泄露 | ⚠️ 标题明文（用户确认不保密），禅道文档列表直接可见 |
| 禅道管理员直接读内容 | ✅ 需要用户 ID 才能解密正文 |
| 密文被篡改 | ✅ GCM auth tag 校验失败，解密报错 |
| 同事看到其他人的备忘录 | ✅ 各自选自己的文档库，互不干扰 |
| 知道用户 ID 后暴力破解 | ⚠️ 无法防护（用户 ID 禅道内可见），已如实告知 |

## 10. 验收标准（P0）

**本地功能**
- 新建/编辑/删除后列表即时刷新；删除有确认；刷新页面数据不丢。
- 置顶的备忘录永远在最前；编辑后自动按时间归位。
- 搜索能命中标题、正文、标签。

**加密同步**
- 启用同步后，选定文档库中出现备忘录文档，标题=备忘录标题（明文），正文为 base64 密文，不含任何明文内容。
- 在另一台设备登录同一禅道账号 → 备忘录自动同步回来。
- 两台设备各改不同备忘录 → 合并后两条都在。
- 一台删除、另一台编辑同一条 → 删除生效（禅道里没文档了）。
- 在禅道里手动删一个备忘录文档 → 下次同步时本地自动移除。
- 同步失败（禅道不可达）时，待同步内容保留在本地（`syncDirty`），下次同步自动重试，UI 显示"待同步 N 条"。
- 未启用同步时，备忘录纯本地，不影响使用。
