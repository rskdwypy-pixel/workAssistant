# 工作助手 · B端轻量后台 UI 改版方案

> 参考风格：Finexis / Green Flag / Bright AI 等「浅色极简 + 卡片式 + 数据可视化」B端 Dashboard
> 范围：`extension/` 下 newtab 页（任务 / Bug / 报告）与设置页
> 原则：**代码只读分析，本方案不改任何现有文件**；改版按阶段渐进落地，Token 优先

---

## 一、目标风格解构（参考图 → 设计语言）

| # | 风格特征 | 具体表现 |
|---|---------|---------|
| 1 | 浅色画布 | 整页浅灰底（#F4F5F7 级别），内容全部装进白色圆角卡片，卡片外留足呼吸感 |
| 2 | 单一视觉锚点 | 每屏只有 1 张彩色/渐变 Hero 卡（如青绿 Total Balance），其余卡片全白，视线自然落在重点数据上 |
| 3 | 三色纪律 | 深墨色（导航/主按钮）+ 青绿色（增长/核心数据）+ 大面积中性灰白，状态色低饱和、小面积使用 |
| 4 | 药丸导航 | 顶部导航激活态为深色药丸（pill），不是下划线；左侧窄图标栏（icon rail） |
| 5 | 问候式页头 | 「Hello again, Alen」大标题 + 一行浅色副文案 + 右侧动作按钮组，取代干巴巴的工具栏 |
| 6 | 克制的图表 | 折线=趋势、柱状=对比、环形=占比、表格=明细；一页图表类型 ≤3 种 |
| 7 | 轻阴影、无分割线 | 阴影几乎不可见（0 1px 2px 级），卡片之间靠间距（8/16/24 体系）分隔，不用 border 堆砌 |

## 二、现状审计（代码只读结论）

**技术形态**：Chrome 扩展 New Tab 页，纯 HTML/CSS/JS 无框架；`newtab.css` 2898 行、`newtab.html` 1243 行、`newtab.js` 11006 行（卡片 DOM 由 JS 动态生成）、`reports.js` 渲染报告模式、`settings.css` 548 行。

### 已有的好底子（保留）
- ✅ `:root` CSS 变量体系完整（颜色/阴影/圆角 4 档），改 Token 即全局生效
- ✅ 字体已是 Inter，符合目标风格
- ✅ 三栏看板结构本身符合 B 端信息层级（状态列 = 明细层）
- ✅ 圆角/阴影已有分级意识（sm/lg/xl）

### 差距清单（按严重度排序）

| 问题 | 证据 | 影响 |
|------|------|------|
| ① 无视觉锚点、无页头层次 | 看板头部只有「📋 今日任务 + 统计数字 + 搜索框」，没有问候语/焦点数据卡 | 第一眼是工具，不是工作台 |
| ② emoji 当图标 | tab 按钮 `📋🐛📊⚙️`、列头 `🔴🟢⚪🟡🔵`、侧栏 `📝🤖🧪` | 平台差异大、颜色不可控，是「廉价感」最大来源 |
| ③ 色彩纪律不足 | 主色靛蓝 #6366f1 与 success 绿、测试按钮橙/紫/青橙四色并存、task-card 左侧 3px 灰条 | 重点信息无法一眼识别 |
| ④ 内联样式泛滥 | newtab.html 中 145 处 `style="..."`（弹窗表单、测试按钮等），newtab.js 内还有动态内联样式 | 无法被 Token 统一治理 |
| ⑤ 零数据可视化 | 本周/本月/连续只有纯文本数字；日历热力图有但视觉存在感弱 | 与目标风格差距最大的一层 |
| ⑥ Tab 为下划线式 | `.tab-btn.active` 底部 2px 线 | 与目标「药丸导航」气质不符 |
| ⑦ 测试按钮暴露在主界面 | 侧栏 `🧪 测试按钮` 四个彩色按钮 | 开发调试物污染正式 UI |
| ⑧ 状态色语义混乱 | 列头用 emoji 颜色表达状态，卡片左侧条用 `--text-muted` 灰 | 状态识别依赖阅读而非扫视 |

## 三、设计 Token 方案（第一阶段，改 `:root` 即见效）

> 策略：**沿用现有变量名，只换值**。`--primary` 被全文件引用，改名成本高，直接映射到新色彩体系即可，`newtab.js` 无需改动。

```css
:root {
  /* ===== 1. 中性画布：浅灰底 + 纯白卡 ===== */
  --bg-base:    #F4F5F7;   /* 页面画布（原 #f8fafc，略降温） */
  --bg-surface: #FFFFFF;   /* 卡片容器 */
  --bg-hover:   #F7F8FA;   /* 行/卡片悬停底色（新增） */

  /* ===== 2. 三色纪律 ===== */
  --ink:        #1D1B34;   /* 深墨紫黑：主按钮、激活态导航（新增，替代 primary 做按钮） */
  --ink-hover:  #2A2749;
  --primary:    #14B8A6;   /* 青绿：核心数据、增长、强调（原靛蓝 #6366f1 → 全局换血） */
  --primary-dark: #0D9488; /* 青绿的深色文字版（白底对比度 3.9:1，仅用于 ≥18px 或图形） */
  --primary-soft: #E6F7F4; /* 青绿的 8% 淡底，用于选中态/标签底 */

  /* ===== 3. 语义色（全部降饱和、小面积） ===== */
  --success: #22C55E;  --warning: #F59E0B;  --danger: #EF4444;
  /* 使用规则：仅用于状态点/徽标/进度条，禁止整块铺底色 */

  /* ===== 4. 文字层级 ===== */
  --text-primary:   #1B1F2E;
  --text-secondary: #5B6472;
  --text-muted:     #9AA3B2;

  /* ===== 5. 边框与阴影：轻到几乎不可见 ===== */
  --border:    #ECEEF2;
  --shadow-sm: 0 1px 2px rgba(16, 24, 40, 0.04);
  --shadow:    0 2px 8px rgba(16, 24, 40, 0.06);          /* hover 专用 */
  --shadow-lg: 0 12px 32px rgba(16, 24, 40, 0.12);        /* 仅弹窗 */

  /* ===== 6. 圆角：统一放大一档（卡片 16 是该风格签名） ===== */
  --radius-sm: 8px;
  --radius:    12px;
  --radius-lg: 16px;   /* 卡片 */
  --radius-xl: 24px;   /* Hero 卡 / 弹窗 */

  /* ===== 7. 间距体系（8 点制，新增供新代码使用） ===== */
  --space-1: 4px;  --space-2: 8px;  --space-3: 12px;
  --space-4: 16px; --space-6: 24px; --space-8: 32px;
}
```

**可访问性（WCAG AA）**：
- 正文 `#1B1F2E` / 白底 ≈ 15:1；次要 `#5B6472` / 白 ≈ 6.9:1，均达标
- 青绿 `#14B8A6` 做正文色不够（≈2.5:1）→ **文本场景一律用 `--primary-dark` #0D9488**，图形/大数字才用亮青绿
- 深墨按钮白字 ≈ 14:1；焦点环统一 `0 0 0 3px rgba(20,184,166,.25)`

## 四、布局改版方案（第二阶段）

### 4.1 页头区（信息层级第 1~2 层）

```
┌──────────────────────────────────────────────────────────────┐
│  下午好 👋 → 「下午好，今天也加油」(20px/600)                    │
│  今天已完成 3 个任务 · 已工作 5.5h        [🔍搜索]  [+ 添加任务] │
├──────────────────────────────────────────────────────────────┤
│ ┌─ Hero卡(青绿渐变) ─┐ ┌─ KPI ─┐ ┌─ KPI ─┐ ┌─ KPI ─┐        │
│ │ 今日工时  5.5h      │ │ 本周完成│ │ 本月完成│ │ 连续天数│       │
│ │ ↑ 较昨日 +1.5h      │ │  12    │ │  48    │ │  7 天  │        │
│ └────────────────────┘ └───────┘ └───────┘ └────────┘        │
└──────────────────────────────────────────────────────────────┘
```

- 现有 `#todayWorkTime`（今日已工作 N h）**从看板头的小绿字升级为 Hero 卡主数据**——它本来就是用户最关心的核心业务数据，符合「第一层 = 核心业务数据」原则
- 原 `task-board-stats`（本周/本月/连续）从纯文本升级为 3 张白底 KPI 迷你卡，数字 22px/700，标签 12px 灰
- Hero 卡是该页唯一彩色卡片（青绿渐变 `linear-gradient(135deg, #2DD4BF, #14B8A6)`），白字，承载主按钮「添加任务」的白底反色按钮

### 4.2 导航区

- `mode-tabs`（任务/Bug/报告）：下划线式 → **药丸分段控件**——容器为白卡内嵌浅灰底（`--bg-base`），激活项为深墨药丸白字，其余灰字；「⚙️ 设置」改为右侧图标按钮
- 左侧栏（日历 + 添加任务 + 智能总结）：保留 300px 结构（避免动 `newtab.js` 大量布局逻辑），但内部全部「卡片化」：日历一张白卡、添加任务一张白卡、报告生成按钮组一张白卡，卡片间距 16px
- `🧪 测试按钮` 整块移出侧栏 → 收进设置页调试区（`settings-ui.js`），主界面归零噪音

### 4.3 看板列与任务卡

- 列头 `🔴 待办` emoji → **8px 圆点 + 文字**：待办=灰点、进行中=青绿点、已完成=浅灰勾；计数徽标用 `--bg-base` 胶囊
- `.task-card`：
  - 删除 `::before` 左侧 3px 色条（这是旧风格残留）→ 优先级/状态改为卡片 meta 行的小徽标（胶囊形，`--primary-soft` 底 + `--primary-dark` 字）
  - 阴影改 `--shadow-sm`，hover 只做 `border-color + shadow`，去掉 `translateY(-2px)` 位移（信息密集区不宜跳动）
  - 进度条：6px 轨道改 4px、圆角胶囊，填充色按状态（进行中=青绿、完成=浅灰绿）
- 日历热力图：5 档绿色 → 5 档青绿（与主色统一），保持 GitHub 式逻辑不变

## 五、组件规范速查（供实施对照）

| 组件 | 规范 |
|------|------|
| 主按钮 | 深墨 `--ink` 底白字，`radius` 12px（或全圆角胶囊），hover `--ink-hover`，禁用 40% 透明 |
| 次按钮 | 白底 + `--border` 描边 + `--text-primary` 字，hover `--bg-hover` |
| 搜索框 | 白底胶囊、左放大镜 SVG 图标、focus 时 `--primary-soft` 外环 |
| Tab/分段控件 | 容器 `--bg-base` 圆角 12，激活项 `--ink` 药丸白字，过渡 150ms |
| 徽标 | 全圆角胶囊、12px、语义色 10% 底 + 深色字（如 success 徽标 = #22C55E12 底 + #15803D 字） |
| 弹窗 | `--radius-xl` 24px、`--shadow-lg`、遮罩 `rgba(29,27,52,0.4)` + blur(4px) |
| Toast | 保持白卡样式，左侧 4px 色条改为左上角状态图标圆片（去「票据感」） |
| 图标 | emoji 全量替换为 24px stroke 1.5~1.75 线性 SVG（内联，无新依赖） |

## 六、数据可视化方案（第三阶段，纯 SVG/CSS，零依赖）

遵循「一页图表 ≤3 种」，本期只做 2 种：

1. **本周完成柱状图**（报告模式或看板侧）：7 根圆角柱，纯 CSS 高度动画；今日柱用主色、其余 `--border` 色，hover 显示 tooltip——对应「趋势/对比」
2. **任务分布环形图**（看板头部或报告页）：待办/进行中/完成 占比，SVG `stroke-dasharray` 实现，中心显示完成率大数字——对应「占比」
3. 表格明细层已有（看板 + 报告列表），不动

> 报告模式（`reports.js` 渲染）的卡片同样套用第三、五章 Token 与卡片规范，属于「换肤」级改动。

## 七、实施路线图

| 阶段 | 内容 | 涉及文件 | 风险 |
|------|------|---------|------|
| P1 Token 换血 | 只改 `:root` 变量值 + 新增 token | `newtab.css`（~30 行） | 极低，即改即见效 |
| P2 组件换肤 | 按钮/Tab/卡片/徽标/日历配色，去 emoji、去 `::before` 色条 | `newtab.css` + `newtab.html` | 低；**class 名保持不变**，`newtab.js` 不动 |
| P3 页头重构 | 问候头 + Hero 卡 + KPI 卡；测试按钮迁入设置 | `newtab.html` + `newtab.js`（头部渲染）+ `settings-ui.js` | 中；涉及 JS 渲染节点 |
| P4 数据可视化 | 柱状图 + 环形图 | `reports.js` / 新增独立模块 | 中 |
| P5 清理 | 消灭 145 处内联样式 → 归入 class；`newtab.js` 动态内联样式收口 | `newtab.html` / `newtab.js` | 中高；需回归拖拽、弹窗、禅道同步 UI |

**关键约束提醒（实施时注意）**：
- `newtab.js` 有 11006 行，卡片 DOM 靠 class 名驱动交互（拖拽/选中/快捷键），**改版必须保持所有现有 class 名向后兼容**，只改样式不改结构名
- 弹窗内联样式（`taskExecution`、`progressInput*` 等）改造时同步收进 `settings.css`/`newtab.css`
- 每阶段完成后用真实入口验证：`./start.sh` → 浏览器加载 `extension/` → 新标签页检查任务增删改、拖拽、Bug 状态流转、报告生成四大主链路
